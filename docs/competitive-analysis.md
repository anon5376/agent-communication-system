## Where ACS sits

The market splits into two camps with a gap between them. The **frameworks** (MetaGPT, CrewAI, LangGraph, AutoGen/MAF, OpenAI Agents SDK) orchestrate LLM calls *inside one program* — their "agents" are code objects sharing a Python/JS process, and adopting them means writing orchestration code in that framework's graph model. The **control surfaces** (OpenHands, Vibe Kanban, claude-squad, Claude Code agent teams) manage real agent *processes*, but coordination is mostly human-as-router — dispatch, watch, review — with either no durable inter-agent protocol or one locked to a single vendor. Claude Code agent teams are the closest shipping feature match (real sessions, shared task list, direct messaging) but are Claude-only, experimental, and file-scatter-based.

ACS's bet — a **vendor-neutral, daemonless message-and-task bus between heterogeneous CLI agents** — lands almost exactly in the empty cell. Only the agent-mail projects and Beads/Gas Town occupy the same local-first, file-backed niche. Against them ACS differentiates on: zero server process (CLI and stdio MCP open `bus.db` directly), supervisor + harness adapters that actually *launch* the agent CLIs (not just coordinate running ones), a complete task lifecycle with claims/leases/review gates, and a ~4MB dependency-free Rust binary + TUI aimed at non-technical operators — a footprint none of the 8–86k★ incumbents match. Its real exposures: no standards interop (MCP server, but no A2A/ACP transport so ACS agents can't join those ecosystems), advisory leases without built-in worktree isolation (claude-squad/Vibe Kanban/Claude Code all isolate checkouts automatically), single-machine scope (no remote/team story where OpenHands and Vibe Kanban have one), thinner human review/planning UX than the kanban tools, and a minimal community/ecosystem against vendor-backed platforms.

## Positioning gaps (genuinely different vs. behind)

- **Different:** only fully daemonless option — CLI and stdio MCP server open `bus.db` directly; even the agent-mail tools need an MCP/server process and every framework/control plane needs a runtime or server stack.
- **Different:** vendor-neutral harness adapters that spawn and supervise real heterogeneous agent CLIs (claude, codex, gemini, kimi, opencode, openai-compatible) — Claude agent teams are Claude-only, and claude-squad/vibe-kanban dispatch agents but provide no inter-agent protocol.
- **Different:** dual byte-compatible implementations on one SQLite schema, including a ~4MB dependency-free Rust binary with a TUI for non-technical operators — no competitor matches the install footprint.
- **Different:** first-class durable task lifecycle (assignment, dependencies, claims, path leases, progress, submission, independent review gates) versus advisory mail in agent-mail or issue-ledger semantics in Beads.
- **Behind:** no standards interop — ACS exposes an MCP server but speaks neither A2A nor ACP, so its agents cannot join the interop ecosystems MAF, OpenHands, and Google are converging on.
- **Behind:** no built-in git worktree/workspace isolation — leases are advisory and docs defer isolation to the harness; claude-squad, Vibe Kanban, and Claude Code all give each agent an isolated checkout automatically.
- **Behind:** single-machine scope — no remote agents, team topology, or cloud backend where OpenHands and Vibe Kanban have one.
- **Behind:** minimal ecosystem and human review UX — no plugin community, examples, or diff-review surface comparable to Vibe Kanban/OpenHands, against competitors with 20k–90k stars and vendor backing.
