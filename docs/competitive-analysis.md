## Where ACS sits

The market splits into two camps with a gap between them, and Hermes Agent now sits partly in the second camp with its own Kanban board (see its row above). The **frameworks** (MetaGPT, CrewAI, LangGraph, AutoGen/MAF, OpenAI Agents SDK) orchestrate LLM calls *inside one program* — their "agents" are code objects sharing a Python/JS process, and adopting them means writing orchestration code in that framework's graph model. The **control surfaces** (OpenHands, Vibe Kanban, claude-squad, Claude Code agent teams) manage real agent *processes*, but coordination is mostly human-as-router — dispatch, watch, review — with either no durable inter-agent protocol or one locked to a single vendor. Claude Code agent teams are the closest shipping feature match (real sessions, shared task list, direct messaging) but are Claude-only, experimental, and file-scatter-based.

ACS's bet — a **vendor-neutral, daemonless message-and-task bus between heterogeneous CLI agents** — lands almost exactly in the empty cell. Only the agent-mail projects and Beads/Gas Town occupy the same local-first, file-backed niche. Against them ACS differentiates on: zero server process (CLI and stdio MCP open `bus.db` directly), supervisor + harness adapters that actually *launch* the agent CLIs (not just coordinate running ones), a complete task lifecycle with claims/leases/review gates, and and a Rust port with a TUI (single `acs` binary, 2,965,176 bytes measured 2026-10-01, see the Positioning gaps section for the measurement conditions); no incumbent footprint was measured, so no size comparison is claimed. Its real exposures: no standards interop (MCP server, but no A2A/ACP transport so ACS agents can't join those ecosystems), advisory path leases, with per-task worktrees now available only in the TypeScript build and only on request (`qagent task claim --worktree`), where claude-squad, Vibe Kanban, Claude Code and Hermes create isolated checkouts for you, single-machine scope (no remote/team story where OpenHands and Vibe Kanban have one), thinner human review/planning UX than the kanban tools, and a minimal community/ecosystem against vendor-backed platforms.

## Positioning gaps (genuinely different vs. behind)

- **Different:** only fully daemonless option — CLI and stdio MCP server open `bus.db` directly; even the agent-mail tools need an MCP/server process and every framework/control plane needs a runtime or server stack.
- **Different (hypothesis, not benchmarked):** vendor-neutral harness adapters that spawn and supervise real heterogeneous agent CLIs (`claude`, `codex`, `gemini`, `kimi`, `cursor`, `grok`, `opencode`, `hermes`, plus any CLI through `command`). Claude agent teams are Claude-only, claude-squad/vibe-kanban dispatch agents without an inter-agent protocol, and Hermes documents non-Hermes worker lanes as not yet a paved path (`kanban-worker-lanes.md:119-125`, commit `e8c97320`).
- **Different:** two implementations on one SQLite schema (TypeScript on `main`, Rust on `rust-port`, which is behind `main` and lacks some commands; see `docs/FULL-GUIDE.md`, Implementation differences). Footprint measured 2026-10-01 on x86_64 Linux with rustc 1.97.0, `cargo build --release` of `rust-port` at `c6df26b` (profile: `strip = true`, thin LTO): `acs` 2,965,176 bytes, `qagent` 4,204,440 bytes. Hermes and the other incumbents were not measured, so no comparison is claimed. The Rust port has not been tested with non-technical operators.
- **Different:** first-class durable task lifecycle (assignment, dependencies, claims, path leases, progress, submission, review gates) versus advisory mail in agent-mail or issue-ledger semantics in Beads. The review gate blocks the assignee from accepting its own work and the operator can override it (`reviewTask` in `src/core/bus.ts`); it does not check model family. Hermes Kanban also has a first-class `review` status, so this is parity on the gate itself, not an edge.
- **Behind:** no standards interop — ACS exposes an MCP server but speaks neither A2A nor ACP, so its agents cannot join the interop ecosystems MAF, OpenHands, and Google are converging on.
- **Parity, partly:** per-task git worktrees exist in the TypeScript build (`claim --worktree`, `"isolation": "worktree"` for the supervisor) but are opt-in, and the Rust port does not implement them. Path leases remain advisory. Hermes Kanban creates `worktree` workspaces per task when asked (`kanban.md:137`); claude-squad, Vibe Kanban and Claude Code isolate checkouts by default.
- **Behind:** no attempt-level run records, exit-code classification of provider failures, or PID-fingerprint crash recovery of the kind Hermes Kanban documents (`kanban.md`, per `proposals/hermes-delta.md` in the AOS repo, rows 1 and 2; not re-read here). ACS has stalled-task detection and requeue (`qagent task stalled`, `task requeue`) in the unreleased `main`.
- **Behind:** single-machine scope — no remote agents, team topology, or cloud backend where OpenHands and Vibe Kanban have one.
- **Behind:** minimal ecosystem and human review UX — no plugin community, examples, or diff-review surface comparable to Vibe Kanban/OpenHands, against competitors with 20k–90k stars and vendor backing.
